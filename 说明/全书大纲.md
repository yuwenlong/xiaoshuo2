**重生文专属红线（本书最高闸，违反即重写）**：

1. **禁系统面板/任务提示/属性数值即时反馈/异能实物化**——金手指只有「记忆」，且受三律约束。
2. **禁买买买流水账**：每笔投资必须依附人物冲突或重大抉择（谁反对、等什么、怕什么），无冲突不成章。

4. **禁时代错误**：凡涉及价格/事件/产品形态，落笔前必过「七、时代锚点表」；拿不准的写区间不写点值。

## 六、写作红线·情节级台账

> 情节级"不能写"清单（与《写作说明》规则级互补；每批动笔前核对）。

1. **禁提前消耗核心事件**：BTC逃顶（卷二）、股灾清仓（卷三）、投零界（卷四）、ChatGPT时刻（卷五）、2026.4.15不裁一人（卷六）——以卷章区间为准，严禁提前引爆或挪用。
2. **禁金手指升级**：全书金手指恒定为「记忆+技术+判断力」，任何"他突然发现还能预知更多"的桥段即违规；记忆只能折旧，不能增值。
3. **禁女主工具化**：林见夏的每次出场必须有她自己的判断与选择（"逻辑链"是她的，不是他的传声筒）；禁写"女主无理由相信男主"。

- **binlog 回放的坑**（ch26）：mysqlbinlog 的 --database 在语句格式下只按「当前默认库」过滤——带库名写、却在别的库下执行的语句会被漏掉（ch26 7:40 一张表「不存在」即此），默认库是本库、改的却是别库的语句反而会被放进来；DROP DATABASE 把被删的库当默认库，所以 -d 也会把删库那句输出，必须用 --stop-position 停在它之前；--stop-position 只作用于命令行上末一个文件，多个文件须一个 mysql 进程一次喂完；导成文本后每个事件的行序是「# at 位置」→「#日期 钟点 server id … end_log_pos」→（use 库）→ SET TIMESTAMP=秒数 →（SET @@session…）→ 语句，紧挨语句上头的是 SET TIMESTAMP 而非钟点，位置要抄 # at 后头那串；mysql 客户端报错是纯文本「ERROR 1146 (42S02) at line N: Table … doesn’t exist」，不带颜色、不指明哪个日志文件；断点续跑用 --start-position（作用于首个文件）配原 --stop-position；逐条 autocommit 的回放以小时计。出处：MySQL 5.1 参考手册 mysqlbinlog 节与 point-in-time 恢复节（2011 存档）。

## 八、结局设计（闭环式，落卷六尾区至终章区）

- **主题闭环**：前世他被"效率"优化掉；今生他站在效率的顶端，选择不优化任何人——"这次，代码是热的"。
- **金手指闭环**：记忆在2022年后折旧殆尽，他靠"后记忆时代"的判断力体系走完最后两卷——挂是入场券，不是终身饭票。

- **感情闭环**：林见夏拿到笔记本那一页并选择封存；婚礼低糖一章带过；终章不洒糖，洒"人"。
- **开放余韵**：终章末镜头给到新一代年轻人——时代继续，风口继续，故事活在读者身上。
